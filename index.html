💡 Core Definition: Four Dimensions of AI 📖 Deep Dive ↗
According to Russell & Norvig, AI definitions span across two primary axes: Thought Process vs. Behavior and Human Fidelity vs. Rationality:
  • Thinking Humanly: Cognitive Science — empirical modeling of human cognitive processes.
  • Acting Humanly: Turing Test (1950) — natural language, KR, automated reasoning, machine learning.
  • Thinking Rationally: Laws of Thought — formal syllogisms and logic to derive uncontestable inferences.
  • Acting Rationally: Rational Agent Approach — choosing actions that maximize expected performance given available percepts.

Intelligent Agents & The PEAS Framework 📖 Deep Dive ↗

Everything you need to know about Agent Architectures, Rationality, and Environment dimensions.

2_Agent Architecture and environment.pdf
📐 Formal Definition: Intelligent Agent & Rationality 📖 Deep Dive ↗
An Agent is anything that perceives its environment through Sensors and acts upon that environment through Actuators:
Agent = Architecture (Hardware / Devices) + Program (Software Implementation)
The abstract mathematical mapping from percept sequences to actions is called the Agent Function: $f: P^* \to A$.
A Rational Agent selects an action that is expected to maximize its performance measure, based on: (1) Percept sequence to date, (2) Built-in prior domain knowledge, and (3) Actions available.
Note: Rationality is NOT omniscience; omniscience implies knowing actual future outcomes in advance!

⚡ 1. Simple Reflex Agent 📖 Deep Dive ↗

▼
Core Principle: Selects actions based only on the current percept, ignoring history of percepts.
Mechanism: Condition-Action rules (e.g., IF car-in-front-is-braking THEN initiate-braking).
Strengths & Limits: Extremely fast; fails completely if environment is partially observable (causes infinite loops).
Exam Example: Standard bimetallic strip room thermostat; basic automated vacuum cleaner with bump sensors.
📐 Official Architecture Diagram 🔍 Zoom (PDF 2, Slide 11)

🧠 2. Model-Based Reflex Agent 📖 Deep Dive ↗

▼
Core Principle: Maintains an internal state to track unobserved aspects of the current world.
Required Knowledge: (1) How the world evolves independently of the agent, and (2) How the agent's actions affect the world.
Strengths & Limits: Handles partial observability by updating internal memory even when sensors cannot see everything.
Exam Example: Reversing a car with rear blind spots by remembering obstacles detected 2 seconds ago.
📐 Official Architecture Diagram 🔍 Zoom (PDF 2, Slide 13)

🎯 3. Goal-Based Agent 📖 Deep Dive ↗

▼
Core Principle: Combines current state knowledge with explicit goal descriptions (desirable situations).
Mechanism: Employs Search and Planning algorithms to compute a sequence of future actions to reach the goal.
Strengths: Highly flexible; if the destination changes, simply replanning with new goal works without altering rule base.
Exam Example: GPS Navigation system planning a route to the airport; 8-puzzle and chess solvers.
📐 Official Architecture Diagram 🔍 Zoom (PDF 2, Slide 15)

⭐ 4. Utility-Based Agent 📖 Deep Dive ↗

▼
Core Principle: Uses a real-valued utility function $U(s)$ that maps world states to real numbers (degrees of happiness/satisfaction).
Decision Criterion: Maximum Expected Utility (MEU) — balances trade-offs when conflicting goals exist (e.g. speed vs. safety vs. fuel economy).
Exam Example: Automated taxi route planner optimizing fare income, passenger ride smoothness, and traffic delay risk.
📐 Official Architecture Diagram 🔍 Zoom (PDF 2, Slide 17)

📚 5. Learning Agent 📖 Deep Dive ↗

▼
4 Distinct Components:
  • Learning Element: Responsible for making improvements based on experience.
  • Performance Element: Responsible for selecting external actions (equivalent to previous agent models).
  • Critic: Evaluates agent's behavior against an external performance standard.
  • Problem Generator: Suggests exploratory actions leading to new, informative experiences (exploration vs. exploitation).
Exam Example: Self-driving car system that improves braking precision after driving on icy roads.

📋 PEAS Framework — Standard Exam Case Studies 📖 Deep Dive ↗

Always state all four components clearly when formulating an agent specification.

P — Performance Measure

The objective criterion used to evaluate how successfully the agent operates in its environment.

E — Environment

The external context, obstacles, and entities with which the agent interacts.

A — Actuators

The hardware and mechanical output mechanisms through which the agent performs actions.

S — Sensors

The perceptual devices and data streams through which the agent perceives its environment.

🌍 The 7 Environment Dimensions (Properties) 📖 Deep Dive ↗

The nature of the environment dictates which agent architecture and search algorithm can be applied.

1. Observability Perception

Fully Observable: Agent's sensors provide access to the complete state of the environment at all points in time (no internal memory needed).
Partially Observable: Sensor noise, blind spots, or missing data require the agent to maintain an internal world model.

Chess (Fully) vs. Poker / Driving (Partially)
2. Determinism Transitions

Deterministic: The next state is completely determined by the current state and the agent's executed action.
Stochastic: Uncertainty and randomness introduce probabilities.
Strategic: Environment is deterministic except for actions of other rival agents.

Chess / Sudoku (Deterministic) vs. Backgammon / Driving (Stochastic)
3. Episodic vs. Sequential Time Memory

Episodic: The agent's experience is divided into independent atomic episodes. Current choice does NOT affect future episodes.
Sequential: The current decision affects all subsequent future decisions (demands long-term planning).

Part Defect Classifier (Episodic) vs. Chess / Driving (Sequential)
4. Dynamism Deliberation

Static: The environment does not change while the agent is deliberating.
Dynamic: The world changes continuously as the agent thinks.
Semi-Dynamic: Environment itself does not change, but the agent's performance score decreases as time passes.

Crossword (Static) vs. Driving (Dynamic) vs. Timed Chess (Semi-Dynamic)
5. Continuity State Space

Discrete: A finite, distinct, clearly countable number of states, percepts, and actions.
Continuous: Smoothly varying values across real numbers (continuous speed, angle, coordinate locations).

Chess / Tic-Tac-Toe (Discrete) vs. Self-driving Car (Continuous)
6. Agent Count Interaction

Single-Agent: Agent solves the task completely by itself without other interacting reasoning entities.
Multi-Agent: Other reasoning agents exist, either Competitive (zero-sum, like chess) or Cooperative (collaborative navigation).

Crossword / Solitaire (Single) vs. Chess / Stock Market (Multi-Agent)
7. Environmental Rules Physics

Known: The physics, outcome transitions, and transition model of the environment are fully given to the agent.
Unknown: The agent must explore and learn how the environment responds before it can plan.

Standard Board Game (Known) vs. Exploring an Alien World (Unknown)

📐 Key Concept: Heuristic Functions & Optimality 📖 Deep Dive ↗
A Heuristic Function $h(n)$ estimates the cheapest path cost from node $n$ to the closest goal state.
  • Admissibility: An admissible heuristic never overestimates the true cost to reach the goal: $0 \le h(n) \le h^*(n)$. Tree-search $A^*$ is guaranteed to be optimal if $h(n)$ is admissible.
  • Consistency (Monotonicity): For every node $n$ and every successor $n'$ generated by action $a$: $h(n) \le c(n, a, n') + h(n')$. Consistency satisfies the triangle inequality. Graph-search $A^*$ is optimal if $h(n)$ is consistent.
  • Rule of Thumb: Consistency $\implies$ Admissibility, but the converse is not always true!

🟢 Greedy Best-First Search 📖 Deep Dive ↗

Evaluation Function: f(n) = h(n)

Behavior: Expands the node that appears closest to the goal based solely on the heuristic $h(n)$.
Evaluation: Not optimal, not complete in infinite spaces (can get stuck in loops). Time: $O(b^m)$, Space: $O(b^m)$ (keeps all nodes in memory).

⭐ A* Search (The Benchmark) 📖 Deep Dive ↗

Evaluation Function: f(n) = g(n) + h(n)

Behavior: Combines exact accumulated path cost $g(n)$ from start with estimated heuristic cost $h(n)$ to goal.
Evaluation: Optimal and complete with admissible / consistent heuristics.
The Fatal Flaw: Memory complexity is $O(b^d)$ — exhausts all RAM within minutes!

💰 Uniform Cost Search (Dijkstra's) 📖 Deep Dive ↗

Evaluation Function: f(n) = g(n)

Behavior: Expands the node with the lowest path cost $g(n)$ so far, ignoring distance to goal ($h(n)=0$).
Evaluation: Complete and optimal if step costs $\ge \epsilon > 0$. Can be very slow because it expands contours uniformly in all directions.

PDF 5: Memory-Bounded Search

Memory-Bounded Heuristic Search

How IDA*, RBFS, and SMA* conquer the exponential $O(b^d)$ space bottleneck of A*.

5_Memory Bounded Search.pdf
⚠️ The $A^*$ Memory Crisis 📖 Deep Dive ↗
$A^*$ keeps all generated nodes in the Open List (frontier) and Closed List. With branching factor $b=10$ and depth $d=10$, $A^*$ generates $\approx 10^{10}$ nodes ($\approx 100$ Gigabytes of RAM)! Long before compute time runs out, $A^*$ crashes due to Out-Of-Memory. Memory-bounded algorithms enforce strict memory caps without discarding optimality.

💥 Standard A* Search 📖 Deep Dive ↗

Space: O(bd) 💥 Crashes RAM!

Stores every expanded state in memory. Complete & optimal, but fundamentally limited by storage capacity.

⚡ IDA* (Iterative Deepening A*) 📖 Deep Dive ↗

Space: O(b·d) ✨ Linear

Analogous to IDDFS, but the cutoff threshold is the $f$-cost limit. Each iteration runs a modified DFS until node $f(n) > \text{limit}$. The next iteration's limit is the smallest $f$-cost that exceeded the previous limit.

🔄 RBFS (Recursive Best-First) 📖 Deep Dive ↗

Space: O(b·d) ✨ Linear

Mimics best-first search in linear memory. Maintains an $f\text{-limit}$ representing the best alternative path available at any ancestor. If current path $f > \text{limit}$, it backs up forgotten child values and switches (can cause thrashing).

🧠 SMA* (Simplified Memory-Bounded) 📖 Deep Dive ↗

Space: O(M) 🧠 Uses All RAM M

Uses all allocated memory buffer $M$. When full, drops the shallowest, highest $f$-cost (worst) node and backs up its value to its parent. Optimal if $M \ge d^*$ (optimal path fits in memory).

Knowledge Representation, Inference & Prolog

How artificial intelligence systems structure, store, and reason over domain facts and rules.

1_Knowledge_Representations.pdf
💡 The DIKW Hierarchy & KR Properties 📖 Deep Dive ↗
Data: Disconnected raw symbols/facts $\to$ Information: Structured data with relational context $\to$ Knowledge: Understanding patterns and principles ("knowing how/that") $\to$ Wisdom: Evaluating reasons ("knowing why").
A successful KR system must fulfill 4 Core Requirements:
  1. Representational Adequacy: Ability to represent all kinds of knowledge required in the domain.
  2. Inferential Adequacy: Ability to manipulate representational structures to derive new knowledge.
  3. Inferential Efficiency: Ability to direct inference mechanisms into the most productive paths.
  4. Acquisitional Efficiency: Ability to easily acquire new knowledge from experts or automated learning.

📊 1. Relational Knowledge 📖 Deep Dive ↗

Knowledge stored in relational database tables with rows (entities) and columns (attributes). Simple, highly standardized, but possesses weak inferential capabilities beyond SQL joins.

🕸️ 2. Inheritable Knowledge (Semantic Nets & Frames) 📖 Deep Dive ↗

Entities organized as nodes in an inheritance hierarchy. Edges represent relationships: IsA (class subset relation) and Instance (class member relation). Properties automatically propagate down the hierarchy (e.g., Canary IsA Bird $\implies$ Canary has wings).

🧮 3. Inferential Knowledge (Predicate Logic) 📖 Deep Dive ↗

Expressed as formal logic sentences with constants, variables, predicates, and quantifiers ($\forall, \exists$). Allows rigorous deductive automated reasoning via the Resolution Refutation Principle.

⚙️ 4. Procedural Knowledge (Production Systems) 📖 Deep Dive ↗

Rules expressed as IF <condition> THEN <action>. Used in expert systems where the Inference Engine matches conditions against Working Memory facts to trigger actions.

⏩ Forward Chaining (Data-Driven) 📖 Deep Dive ↗

Bottom-up reasoning: Starts with known facts in Working Memory, fires matching rules, and adds conclusions until goal is reached.

  • Starting Point: Initial set of facts in Working Memory.
  • Conflict Set: All rules whose premises are satisfied by current facts.
  • Conflict Resolution Strategies:
    • Refractory: A rule will not fire twice on the identical piece of data (prevents infinite loops).
    • Recency: Prefers rules matching newly generated facts (time-tags).
    • Specificity: Prefers rules having more detailed/specific condition clauses.
  • Best Suited For: Design, synthesis, configuration, and monitoring tasks.

⏪ Backward Chaining (Goal-Driven) 📖 Deep Dive ↗

Top-down reasoning: Starts with a hypothesis (goal) to prove, finds rules that conclude it, and recursively verifies their premises.

  • Starting Point: Desired goal / hypothesis query.
  • Process: Scans rule base for rules whose THEN clause matches the goal.
  • Sub-goals: Unverified premises become new sub-goals that must be proven.
  • User Interaction: Asks user for missing facts only if no rules can prove the premise.
  • Prolog Engine: Standard Prolog execution operates strictly via depth-first backward chaining with backtracking.
  • Best Suited For: Diagnosis, medical consultation (MYCIN), troubleshooting.

💻 Logic Programming & Prolog Essentials 📖 Deep Dive ↗

Based on Robert Kowalski's landmark equation: Algorithm = Logic + Control.

1. Facts (Unit Clauses)
parent(tom, bob).
female(pam).
sunny.

Unconditional truths. Always end with a period .

2. Rules (Horn Clauses)
grandparent(X, Z) :-
  parent(X, Y), parent(Y, Z).

Head :- Body read as: "Head is true IF Body is true". Commas represent logical AND.

3. Queries (Goals)
?- grandparent(tom, Who).
Who = bob ;
false.

Submitted to the interpreter. Uses SLD resolution and unifies variables (starts with uppercase).

⚡ De Morgan's Laws 📖 Deep Dive ↗

¬(p ∧ q) ≡ ¬p ∨ ¬q
¬(p ∨ q) ≡ ¬p ∧ ¬q
¬(∀x P(x)) ≡ ∃x ¬P(x)
¬(∃x P(x)) ≡ ∀x ¬P(x)

🔗 Conditional & Contrapositive

(p → q) ≡ (¬p ∨ q)
(p → q) ≡ (¬q → ¬p) [Contrapositive]
¬(p → q) ≡ (p ∧ ¬q)
(p ↔ q) ≡ (p → q) ∧ (q → p)

🔀 Distributive & Associative Laws

p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)
p ∨ (q ∧ r) ≡ (p ∨ q) ∧ (p ∨ r)
(p ∧ q) ∧ r ≡ p ∧ (q ∧ r)

🧽 Absorption & Idempotent Laws

p ∨ (p ∧ q) ≡ p
p ∧ (p ∨ q) ≡ p
p ∨ p ≡ p  |  p ∧ p ≡ p
¬(¬p) ≡ p [Double Negation]

📐 Quantifier Distributions

∀x (P(x) ∧ Q(x)) ≡ ∀x P(x) ∧ ∀x Q(x)
∃x (P(x) ∨ Q(x)) ≡ ∃x P(x) ∨ ∃x Q(x)
∀x P(x) ∨ ∀x Q(x) ⟹ ∀x (P(x) ∨ Q(x))
